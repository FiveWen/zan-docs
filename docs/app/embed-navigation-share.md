# 导航与分享

本页列出商城当前代码中已存在的 v0 消息，用于兼容性评估。新 App 只有在双方能力表确认后才实现对应消息；未列入本次范围的消息可明确返回“不支持”。

## 当前消息基线

| `type` | 方向 | 主要字段 | 语义 |
|---|---|---|---|
| `PUSH` | H5 → App | `url` | 由 App 打开指定商城/业务页面 |
| `NATIVE_PUSH` | H5 → App | `url` | 打开 App 原生或约定页面；具体路由需单独确认 |
| `BACK` | H5 → App | 无 | 返回或关闭当前 WebView |
| `SET_TITLE` | H5 → App | `data.title` | 同步当前页面标题 |
| `SHARE_WECHAT` | H5 → App | `data` | 调起微信分享 |
| `SHARE` | H5 → App | `data` | 历史通用分享消息，字段随场景变化 |

`PUSH`/`NATIVE_PUSH` 不能直接打开任意外部 URL。App 应按双方确认的域名、scheme 和页面清单校验。

## 微信分享

商城当前会发送：

```js
{
  type: 'SHARE_WECHAT',
  data: {
    // 具体字段由分享场景和协议版本确定
  }
}
```

正式接入前必须确认标题、描述、图片、链接和渠道字段。分享链接不能携带 token、session 等认证信息。

当前 v0 发送仅表示消息已投递到 App，不代表用户完成分享。若项目要求区分成功、取消和失败，双方需要定义带关联标识的回调协议；在该协议发布前，App 与 H5 都不能伪造分享成功结果。

## 返回与关闭

收到 `BACK` 后，App 根据容器栈返回上一页或关闭当前 WebView。若页面可在 WebView 内自行返回，双方需确认优先级，避免一次操作返回两层。
