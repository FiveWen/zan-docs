# 支付协议

支付由商城负责下单、选择支付方式、获取预支付参数和后台查单；App 只负责按协议拉起对应原生支付能力。App 返回结果不能替代商城后台订单状态。

## 标准流程

1. 用户在商城提交订单；
2. 商城后台创建支付并返回预支付参数；
3. H5 将支付意图发送给 App；
4. App 拉起原生支付、小程序或对应支付容器；
5. App 将用户操作结果通知 H5；
6. H5 返回前台后查询商城后台订单状态；
7. 后台已支付才进入支付成功页面。

## 当前兼容消息

现有代码包含支付宝小程序消息：

```js
{
  type: 'ALIPAY_XCX',
  data: '<商城后台返回的预支付数据>'
}
```

当前 H5 回调入口可接收：

```js
window.onAppMessage({
  type: 'PAY_RESULT',
  data: {
    status: 'success' | 'fail',
    message: '<可选说明>',
    tid: '<订单号>'
  }
})
```

这些字段属于当前兼容实现，不代表所有支付方式已经形成稳定统一协议。微信、小程序跳转、支付宝及其他渠道必须在项目能力表中分别确认预支付字段、目标应用和返回方式。

## 结果判定

- `PAY_RESULT.success` 仅表示 App/支付容器报告成功，H5 仍需查单；
- `fail`、取消、无回调或超时后也需要按业务规则查单；
- 查询结果为未支付时保持待支付状态，不跳成功页；
- 不重复创建支付，不因重复回调重复跳转；
- App 返回商城时应保留订单号和可恢复的页面上下文。

## 上线前确认项

- 支持的支付渠道和 App 版本；
- 每个渠道的预支付请求结构；
- 原生、小程序或外部应用的拉起方式；
- 返回 H5 的生命周期及 `PAY_RESULT` 触发时机；
- 取消、失败、处理中和最终成功的查单策略。
