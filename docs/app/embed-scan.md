# 扫码协议

商城当前兼容的扫码请求为：

```js
{ type: 'SCAN_CODE' }
```

收到消息后，App 应检查相机权限并打开原生扫码页面。用户取消、权限拒绝、无法识别和扫码成功必须是不同结果。

## 当前协议状态

现有商城代码在不同 App 中存在“App 自行处理后续导航”和“结果返回 H5”两种历史模式，统一扫码回调消息尚未发布。因此新 App 在开发前必须选择并确认其中一种：

1. **App 闭环**：App 解析结果并按双方页面规则完成导航；
2. **H5 闭环**：App 将二维码原文返回 H5，由商城校验并跳转。

推荐后续统一采用 H5 闭环，因为商城可以集中校验允许域名、订单码和商品码。但在回调 `type`、关联标识和错误码正式发布前，不应自行创造生产字段。

## 安全与交互要求

- App 不直接执行二维码中的任意 URL；
- 扫码结果必须按白名单交给商城或 App 路由处理；
- 用户取消应安静恢复按钮，不提示系统错误；
- 权限拒绝应提供可理解的授权指引；
- 重复点击只能打开一个扫码流程；
- 从后台恢复或销毁 WebView 后，不回调到失效页面。
