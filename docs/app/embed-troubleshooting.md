# 错误处理与联调

## 联调环境

聚宝赞提供测试商城域名、`siteId`、`hostApp` 和测试账号。App 方提供安装包、系统版本、设备信息及可复现步骤。日志和截图不得包含完整 token、session、手机号等敏感信息。

## 联调顺序

1. 普通浏览器打开商城，确认未误入 App 链路；
2. App WebView 打开入口，确认 UA、`hostApp` 和消息 handler；
3. 完成后台商城登录，验证刷新、切账号和 401 恢复；
4. 按能力表逐项验证导航、返回、分享、扫码和支付；
5. 验证取消、权限拒绝、断网、重复点击和 App 前后台切换；
6. 验证 Mall ↔ Ucenter 往返及历史网页业务。

## 常见故障

| 现象 | 优先检查 |
|---|---|
| 商城按普通网页运行 | UA、`hostApp`、站点配置、Bridge 是否真实注入 |
| H5 发消息但 App 无响应 | handler 名称、消息包装、注入时机和 JSON 解析 |
| 登录后仍反复登录 | 后台凭据验证、站点匹配、Mall/Ucenter 会话写入 |
| 返回上一页多退一层 | H5 history 与 App `BACK` 的处理优先级 |
| 分享成功但 H5 判断失败 | 是否错误地把消息投递或固定超时当作最终结果 |
| 扫码无结果 | 当前项目采用 App 闭环还是 H5 闭环、权限和回调状态 |
| 支付后页面状态不正确 | `tid`、App 返回时机、`PAY_RESULT` 和后台查单 |

## 验收清单

- 主流程、取消和失败均有明确结果；
- 重复操作不会创建多个原生流程；
- 前后台切换与 WebView 重建不产生旧回调；
- 普通浏览器、微信和小程序不误触发；
- 支付成功由商城后台确认；
- 双方记录最终协议版本与能力矩阵。
